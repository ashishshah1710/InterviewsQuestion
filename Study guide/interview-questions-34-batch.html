Java 17+ (Questions 1–10)

1. Benefits of sealed classes (Java 17)

Java 17

Sealed classes/interfaces restrict which classes can extend or implement them using permits. The compiler knows the full set of subtypes.

BenefitWhy it matters
Exhaustive pattern matchingswitch on sealed hierarchy — compiler warns if a case is missing
Controlled domain modelPayment types: Card | UPI | Wallet only — no random subclasses
Better API designLibrary authors expose fixed extension points
Safer refactoringAdding a new permitted subtype forces updating all switches
public sealed interface Shape permits Circle, Rectangle, Triangle { }

public final class Circle implements Shape {
    private final double radius;
    public Circle(double radius) { this.radius = radius; }
}

// Exhaustive switch (Java 21+)
double area = switch (shape) {
    case Circle c    -> Math.PI * c.radius() * c.radius();
    case Rectangle r -> r.width() * r.height();
    case Triangle t  -> t.area();
    // no default needed — compiler checks all permitted types
};

2. Virtual threads (Java 21) in high-load systems

Java 21 · Concurrency

Platform threads (1:1 with OS threads) are expensive — ~1MB stack, limited to thousands. Virtual threads are lightweight JVM-managed threads; blocking I/O no longer wastes a precious OS thread.

Platform threadsVirtual threads
~few thousand max practicalMillions possible
Blocking HTTP/DB ties up OS threadBlock releases carrier thread — high concurrency for I/O-bound work
Thread pool tuning criticalOften Executors.newVirtualThreadPerTaskExecutor()
// Spring Boot 3.2+: spring.threads.virtual.enabled=true
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    List<Future<OrderDto>> futures = orderIds.stream()
        .map(id -> executor.submit(() -> orderClient.fetch(id)))
        .toList();
}

// Best for: REST APIs waiting on DB/HTTP. Not for: CPU-heavy computation (use platform threads + pool).
Interview line: "Virtual threads improve throughput for I/O-bound request handling by removing platform thread pool exhaustion — each request can have its own virtual thread without tuning a 200-thread Tomcat pool."

3. Optional.map() vs Optional.flatMap()

Java 8+
MethodFunctionResult type
map(f)T → UOptional<U>
flatMap(f)T → Optional<U>Optional<U> (no nested Optional)
Optional<User> user = userRepo.findByEmail("a@x.com");

// map — mapper returns plain value
Optional<String> city = user.map(User::getCity);  // Optional<String>

// flatMap — mapper returns Optional (chaining lookups)
Optional<String> zip = user.flatMap(User::getAddress)   // Optional<Address>
                           .flatMap(Address::getZipCode); // Optional<String>

// WRONG: user.map(User::getAddress) → Optional<Optional<Address>> effectively awkward
// RIGHT: user.flatMap(User::getAddress) → Optional<Address>

4. Serial vs Parallel vs G1 garbage collectors

JVM
CollectorThreadsHeap sizeUse case
SerialSingle GC threadSmall (< ~100MB)Client apps, single-core, minimal footprint
Parallel (Throughput)Multiple GC threadsMedium–largeBatch jobs — maximize throughput, accept longer pauses
G1 (Garbage-First)Parallel + concurrentLarge (> 4GB typical)Server apps — target predictable pause times (default JDK 9+)

G1 divides heap into regions, collects regions with most garbage first, and aims for -XX:MaxGCPauseMillis. Serial stops the world with one thread; Parallel stops the world but uses multiple threads; G1 mixes concurrent marking with incremental evacuation.

# Examples
java -XX:+UseSerialGC -jar small-client.jar
java -XX:+UseParallelGC -jar batch-job.jar
java -XX:+UseG1GC -XX:MaxGCPauseMillis=200 -jar spring-boot.jar

5. How var helps with type inference (Java 10+)

Java 10

var lets the compiler infer the type from the initializer. Variable is still statically typed — not dynamic typing.

var list = new ArrayList<String>();  // ArrayList<String>
var map  = Map.of("k", 1);             // Map<String, Integer>
var path = Path.of("/tmp", "data.json");

// Good: long generic types
var response = restTemplate.exchange(url, HttpMethod.GET, entity, OrderDto.class);

// Invalid: var without initializer, method params, fields (except local)
// var x;  // compile error

Use when type is obvious from RHS; avoid when it hurts readability (var result = process() — unclear type).

6. CopyOnWriteArrayList vs ArrayList

Collections
ArrayListCopyOnWriteArrayList
Thread-safeNoYes (copy-on-write)
ReadFast O(1)Fast — no locks on read
WriteFast O(1) amortizedSlow — copies entire array
IteratorFail-fast on concurrent modSnapshot iterator — no ConcurrentModificationException

Use CopyOnWriteArrayList when reads dominate (listener lists, cache snapshots). Use ArrayList for single-threaded or externally synchronized frequent writes.

7. Purpose of CompletableFuture

Async

Non-blocking composition of asynchronous tasks — chain, combine, handle errors without callback hell.

CompletableFuture<User> userFuture =
    CompletableFuture.supplyAsync(() -> userService.load(userId));

CompletableFuture<OrderSummary> summary = userFuture
    .thenCompose(user -> orderService.loadOrdersAsync(user.getId()))
    .thenApply(orders -> new OrderSummary(orders))
    .exceptionally(ex -> OrderSummary.empty());

// Combine two independent calls
CompletableFuture<Dashboard> dash = userFuture
    .thenCombine(recommendationFuture, Dashboard::new);

userFuture.orTimeout(3, TimeUnit.SECONDS);

Used in microservices to parallelize independent remote calls and merge results.

8. Pattern matching for switch (Java 17+ / 21+)

Java 17+

Combines type test, cast, and deconstruction in switch — less boilerplate than instanceof chains.

// Before
String formatted;
if (obj instanceof Integer i) formatted = String.format("int %d", i);
else if (obj instanceof String s) formatted = String.format("String %s", s);
else formatted = obj.toString();

// After (Java 21)
String formatted = switch (obj) {
    case Integer i -> String.format("int %d", i);
    case String s   -> String.format("String %s", s);
    case null       -> "null";
    default         -> obj.toString();
};

// With sealed types — compiler ensures exhaustiveness

10. Immutability and enforcing it in Java

Design

An immutable object’s state cannot change after construction — thread-safe, safe to share, good for value objects.

public final class Money {
    private final BigDecimal amount;
    private final String currency;

    public Money(BigDecimal amount, String currency) {
        this.amount = amount;
        this.currency = currency;
    }
    public BigDecimal getAmount() { return amount; }
    public String getCurrency() { return currency; }
    // no setters
}

// Collections: List.copyOf(), Map.copyOf(), unmodifiable wrappers
// Defensive copy in constructor for mutable fields:
public Person(String name, List<String> tags) {
    this.name = name;
    this.tags = List.copyOf(tags);
}

// Records (Java 16+) — immutable data carriers by default
public record Point(int x, int y) { }

11. How dependency injection works in Spring

Spring Core

Spring IoC container creates objects, resolves dependencies, and injects them — you define beans, Spring wires the graph.

@Service
public class OrderService {
    private final PaymentClient paymentClient;
    private final OrderRepository orderRepo;

    // Constructor injection (recommended — immutable, testable)
    public OrderService(PaymentClient paymentClient, OrderRepository orderRepo) {
        this.paymentClient = paymentClient;
        this.orderRepo = orderRepo;
    }
}

// Container startup:
// 1. Component scan finds @Component/@Service/@Repository
// 2. Creates bean definitions
// 3. Instantiates beans, injects dependencies (topological order)
// 4. @PostConstruct, BeanPostProcessors, proxies (AOP, @Transactional)

12. Role of @Configuration and @Bean

Spring Core

@Configuration marks a class as a source of bean definitions. @Bean methods register objects in the container (third-party libs, custom clients).

@Configuration
public class AppConfig {

    @Bean
    public RestTemplate restTemplate(RestTemplateBuilder builder) {
        return builder
            .setConnectTimeout(Duration.ofSeconds(2))
            .setReadTimeout(Duration.ofSeconds(5))
            .build();
    }

    @Bean
    @ConditionalOnProperty(name = "feature.x.enabled", havingValue = "true")
    public FeatureClient featureClient() {
        return new FeatureClient();
    }
}

@Configuration classes are proxied so repeated @Bean method calls return the same singleton instance.

14. Secure Spring Boot REST APIs with JWT

Security

Stateless: client sends Authorization: Bearer <jwt>; resource server validates signature and claims.

@Configuration
@EnableWebSecurity
@EnableMethodSecurity
public class SecurityConfig {
    @Bean
    SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(csrf -> csrf.disable())
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**").permitAll()
                .anyRequest().authenticated())
            .oauth2ResourceServer(oauth -> oauth.jwt(Customizer.withDefaults()))
            .build();
    }
}

// application.yml
spring.security.oauth2.resourceserver.jwt.issuer-uri: https://auth.example.com/realms/app

18. @ControllerAdvice vs @ExceptionHandler

Spring MVC
AnnotationScope
@ExceptionHandlerOn a method — handles exceptions for that controller (or globally if on @ControllerAdvice)
@ControllerAdviceClass-level — global exception handling across all controllers
@ControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(NotFoundException.class)
    public ResponseEntity<ErrorDto> handleNotFound(NotFoundException ex) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(new ErrorDto(ex.getMessage()));
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorDto> handleValidation(MethodArgumentNotValidException ex) {
        return ResponseEntity.badRequest().body(toErrorDto(ex));
    }
}

19. Async method execution in Spring Boot

Async 
@EnableAsync
@SpringBootApplication
public class Application { }

@Service
public class NotificationService {

    @Async("emailExecutor")
    public CompletableFuture<Void> sendEmail(String to, String body) {
        mailClient.send(to, body);
        return CompletableFuture.completedFuture(null);
    }
}

@Configuration
@EnableAsync
public class AsyncConfig {
    @Bean(name = "emailExecutor")
    public Executor emailExecutor() {
        ThreadPoolTaskExecutor ex = new ThreadPoolTaskExecutor();
        ex.setCorePoolSize(5);
        ex.setMaxPoolSize(20);
        ex.setQueueCapacity(100);
        ex.initialize();
        return ex;
    }
}

@Async methods must be called from another Spring bean (proxy), not same class.

25. Palindrome number without converting to string

DSA 
public static boolean isPalindrome(int x) {
    if (x < 0) return false;
    if (x != 0 && x % 10 == 0) return false; // 10, 100 not palindrome

    int reversed = 0;
    int original = x;
    while (x > 0) {
        reversed = reversed * 10 + x % 10;
        x /= 10;
    }
    return reversed == original;
}
// 121 → true, 123 → false. Time O(log10 n), Space O(1)

26. Sort a stack using another stack

DSA 
public static void sortStack(Stack<Integer> input) {
    Stack<Integer> temp = new Stack<>();
    while (!input.isEmpty()) {
        int x = input.pop();
        while (!temp.isEmpty() && temp.peek() > x) {
            input.push(temp.pop());
        }
        temp.push(x);
    }
    while (!temp.isEmpty()) {
        input.push(temp.pop());
    }
}
// Each element moved at most twice — O(n²) worst case, O(1) extra stack

27. Maximum sum subarray — Kadane's algorithm

DSA 
public static int maxSubArraySum(int[] nums) {
    int maxSoFar = nums[0];
    int maxEndingHere = nums[0];
    for (int i = 1; i < nums.length; i++) {
        maxEndingHere = Math.max(nums[i], maxEndingHere + nums[i]);
        maxSoFar = Math.max(maxSoFar, maxEndingHere);
    }
    return maxSoFar;
}
// [-2,1,-3,4,-1,2,1,-5,4] → 6 (subarray [4,-1,2,1])
// Time O(n), Space O(1)

30. SQL — 2nd highest salary in a department

SQL 
-- Window function (modern, clear)
SELECT dept_id, employee_id, name, salary
FROM (
    SELECT *,
           DENSE_RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rnk
    FROM employees
) ranked
WHERE rnk = 2;

-- Subquery alternative
SELECT e.*
FROM employees e
WHERE e.salary = (
    SELECT MAX(salary) FROM employees e2
    WHERE e2.dept_id = e.dept_id AND e2.salary < (
        SELECT MAX(salary) FROM employees e3 WHERE e3.dept_id = e.dept_id
    )
);
